# Project Portfolio Evidence Guide

A strong project entry should show evidence of engineering work, not only a visual demo.

## Recommended evidence
For each project, document the problem, architecture and data flow, security boundaries, testing, limitations, reproducibility, and notable engineering changes.

## Good repository signals
Prefer concrete artifacts such as CI workflows, automated tests, security policies, architecture diagrams, reproducible setup instructions, and meaningful commit history.

Avoid claiming production readiness when a repository is academic, experimental, or a demonstration. Clear scope and documented limitations make technical work easier to evaluate.
